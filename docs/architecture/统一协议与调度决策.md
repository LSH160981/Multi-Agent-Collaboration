# 统一协议与调度决策

这份文件对应第三轮补强：

- `scripts/protocol_lib.py`
- `scripts/staffing_decision.py`
- `scripts/recruit_team.py`
- `scripts/runtime_dispatch.py`
- `scripts/runtime_orchestrator.py`

## 1. 为什么要补这一层

前两轮已经有：
- task packet
- staged runtime
- recovery/repair/resume
- `/mac` 安装桥
- 自动学习原型

但还缺一个核心中间层：

> **统一协议 + 复用/招聘决策 + orchestration 执行骨架**

没有这一层，后面的 runtime、巡检、评分、自进化都会各写各的 JSON，最终越改越散。

---

## 2. 统一协议

统一协议来源：
- `skills/Multi-Agent-Collaboration/通信协议.json`

现在通过：
- `scripts/protocol_lib.py`

提供：
- 协议读取
- required 字段校验
- `task_assign` 构造
- `review_scorecard` 构造
- `recovery_action` 构造

这意味着之后所有 A2A 消息都可以复用同一套协议，而不是各脚本自由发挥。

---

## 3. 复用/招聘决策

新增：
- `scripts/staffing_decision.py`

它的职责是：
- 根据 group plan 中的角色需求
- 结合当前已有 agent/session 情况
- 判断：
  - `reuse` 复用已有 agent/session
  - `hire` 启用候选 agent 作为新回合/待扩张对象

当前决策依据：
- 角色 → 候选 agent 池映射
- 是否已有 session
- session 新鲜度

这还不是最终版 HR 系统，但已经把“优先复用，缺口再扩张”落成代码了。

---

## 4. 编组策略

`recruit_team.py` 现在已经支持：
- `single-group`
- `dual-group`

并且组策略写死为：
- A 组：`stable`
- B 组：`aggressive`

同时给每个成员补了 boundary：
- 只处理分配任务
- 不直接联系用户

这和你的公司化边界要求一致。

---

## 5. runtime dispatch

`runtime_dispatch.py` 现在会：
- 校验消息是否满足协议
- 可把旧 payload 自动包成 `task_assign`
- 再发给真实 OpenClaw agent

也就是说：
- dispatch 不再只是“发一段字符串”
- 而是先经过协议层再发送

---

## 6. runtime orchestrator

`runtime_orchestrator.py` 现在真正串起：
1. `mac_cli.py` 解析任务
2. `recruit_team.py` 编组
3. `staffing_decision.py` 做复用/招聘决策
4. 构造 coordinator packets
5. 下发给：
   - 主Agent
   - AgentPool
   - 审核Agent
   - 检查Agent
6. 落盘：
   - task_packet
   - group_plan
   - staffing
   - coordinator_packets
   - runtime-results

---

## 7. 当前意义

这次补强以后，仓库里已经形成三层：

### 第一层：任务理解
- `mac_cli.py`
- `recruit_team.py`

### 第二层：协议与决策
- `protocol_lib.py`
- `staffing_decision.py`
- `runtime_dispatch.py`

### 第三层：执行与恢复
- `stage1/2/3`
- `runtime_orchestrator.py`
- `inspect_and_recover.py`
- `repair/validate/resume`

这比之前更接近“长期运行的公司制多 agent runtime”。

---

## 8. 还要继续补什么

下一步最值得补的是：
- 更正式的 schema 文件（task/handoff/score/recovery 分拆）
- 更真实的 `sessions_send` / `sessions_history` 工具化编排
- AgentPool 的权重、淘汰、重建逻辑
- 主Agent 去重前查看“曾经已发给用户的结论”
