# 测试脚本

安装完 Multi-Agent-Collaboration 后，建议按下面顺序做验收。

---

## 1. 基础安装自检

```bash
./scripts/install-selfcheck.sh
```

确认：
- 主 skill 已安装
- `/mac` 命令桥已安装
- `mac-system/` 目录已初始化

---

## 2. Agent 两两握手测试

作用：验证各 agent 是否真的能工作、能否按角色回复。

```bash
./tests/test_agent_handshake.py
```

默认会让以下角色互相打招呼：
- `main-ceo`
- `pool-hr`
- `review-judge`
- `inspect-patrol`

期望：
- 每个目标 agent 都能回复
- 回复格式类似：`我是XXagent，我的能力是XXX`

输出：
- `examples/generated/tests/handshake-report.json`

---

## 3. 静默任务测试

作用：验证多 agent 还能再次工作，而不是只有第一次握手能通。

默认任务就是你要求的这个方向：

```bash
./tests/test_silent_task.py
```

默认任务：

```text
/mac 搜索 GitHub 最近 7 天 star 涨得最快的 10 个项目，总结共同特点。
```

期望输出：
- `task-packet.json`
- `group-plan.json`
- `native-session-results.json`
- `silent-task-report.json`

目录：
- `examples/generated/tests/silent-task/`

---

## 4. 恢复烟雾测试

作用：验证巡检、repair、resume 能不能闭环。

```bash
./tests/test_recovery_pipeline_smoke.py
```

期望：
- 能识别 broken state
- 能 repair / resume
- 能重新验证 pipeline-state

---

## 5. 原生 session 调度 demo

作用：验证系统已经不只是本地写 JSON，而是真的通过 OpenClaw agent/session 能力派单。

```bash
./scripts/runtime_sessions.py "/mac 调研最近 30 天值得关注的 OpenClaw 多Agent 项目，并给出改造建议"
```

输出目录：
- `examples/generated/native-sessions/`

---

## 6. staged pipeline demo

```bash
./scripts/run_staged_pipeline.py "/mac 调研最近 30 天值得关注的 OpenClaw 多Agent 项目，并给出改造建议"
```

适合验证：
- stage1 规划
- stage2 worker
- stage3 review/final
- 中断后的恢复推进

---

## 7. TUI 观察建议

如果你想看到多 agent 真正协同的过程，可以：

1. 开多个 SSH 会话
2. 分别执行 `openclaw tui`
3. 用 `/agent` 切到不同 agent
4. 观察不同 agent 的独立 session

---

## 8. 失败时先看什么

### 先看 session
```bash
openclaw sessions --all-agents
```

### 再看 agent 列表
```bash
openclaw agents list
```

### 再看主状态
```bash
openclaw status
```

### 再看恢复脚本
```bash
./scripts/inspect_and_recover.py ~/.openclaw/workspace --stale-minutes 30
```

---

## 9. 最低验收标准

至少满足：
- 握手测试通过
- 静默任务测试通过
- 恢复烟雾测试通过

只有这三项都过了，才说明这个 skill 达到“安装后可实际使用”的最低标准。
