# 安装与使用

> 说明：本文件现在承担真正的安装入口、默认接管说明、安装后测试导航，不再只是历史手稿占位。

## 安装

推荐直接安装两个 skill：

- `skills/Multi-Agent-Collaboration/`
- `skills/mac/`（推荐，一并提供 `/mac` 命令桥；本仓库现已内置）

或者直接运行：

```bash
./scripts/default-takeover-setup.sh
```

如有需要，重新打开 session 或重启 gateway 让 skills 刷新。

## 安装前需要确认的 OpenClaw 配置

本 skill 的“真正多 Agent 协作”依赖 OpenClaw 原生 agent-to-agent 与 session 能力。

请确认真实配置字段是：

```json
{
  "tools": {
    "agentToAgent": {
      "enabled": true,
      "allow": [
        "main-ceo",
        "pool-hr",
        "review-judge",
        "inspect-patrol",
        "exec-worker-1"
      ]
    }
  }
}
```

如果你希望像手稿里那样“允许所有当前 agent”，正确做法不是写错字段，而是把当前已知 agent id 全部写进 `tools.agentToAgent.allow`。

> 注意：真实 schema 是 `tools.agentToAgent.enabled` 与 `tools.agentToAgent.allow`，不是别的旧字段写法。

如果后续新增 specialist agent，也应同步补进 allow 列表。

同时建议：
- `tools.sessions.visibility = all`（如果你的环境里有这类可见性配置）
- 主 skill 与 `/mac` 命令桥安装到共享 skills 目录
- 新开 session 后再测试 `/mac`

## 安装完成后的默认目标态

安装完成后，默认应满足：

- 复杂任务先由 **主Agent** 接住
- 显式 `/mac <任务>` 必须进入多会话协作
- 默认常驻核心角色只保留：**主Agent / 审核Agent / 检查Agent / AgentPool**
- 其他 specialist 仅按需创建或复用
- **只有主Agent 可以面向用户输出**

如果默认接管导致普通任务被过度多会话化，应优先退回主Agent 单会话或最小团队。

## 使用方式（最简版）

只记住 3 种：

### 1. 直接说任务
安装后，复杂任务默认就走本 skill。

### 2. 用 `/mac`
这是最直接的强制入口。

```text
/mac 帮我做一个多步骤调研，并输出结构化报告
```

### 3. 直接点名 skill

```text
使用 Multi-Agent-Collaboration skill 完成这个任务
```

## 你真正需要理解的就一句话

**安装完后，普通复杂任务默认就归它管；想强制进入多 Agent，就用 `/mac`。**

## 安装后测试（推荐顺序）

### 测试 1：安装自检

```bash
./scripts/install-selfcheck.sh
```

目标：确认角色目录、脚本、协议、测试模板齐备。

### 测试 2：核心角色互认

```bash
./scripts/test_agent_handshake.py
```

目标：验证主Agent、审核Agent、检查Agent、AgentPool 能互报身份与职责。

### 测试 3：静默任务测试

```bash
./scripts/test_silent_task.py
```

目标：验证内部协作过程中不会把中间噪音直接抛给用户。

### 测试 4：runtime orchestrator smoke

```bash
./scripts/test_runtime_orchestrator_smoke.py
```

目标：验证编组、派发、收口相关关键落盘文件生成正常。

### 测试 5：恢复链路 smoke

```bash
./scripts/test_recovery_pipeline_smoke.py
```

目标：验证恢复相关脚本和流程没有明显断链。

### 可选：原生 session 调度 demo

```bash
./scripts/runtime_sessions.py "/mac 调研最近 30 天值得关注的 OpenClaw 多Agent 项目，并给出改造建议"
```

## 注意

- 只有主Agent可以联系用户
- 非主Agent禁止与用户通信
- 所有通信优先 JSON 结构化
- `/mac` 最稳的实现方式是增加一个 `mac` 命令桥 skill（本仓库已补齐 `skills/mac/SKILL.md`）
- 优先复用已有 session / agent；缺角色再扩张
- 恢复时先 probe / 催办 / 续跑，再考虑重派或重建
- 不同任务、不同 session 的日志与状态应隔离，避免上下文污染
