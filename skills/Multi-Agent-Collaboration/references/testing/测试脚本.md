# 测试脚本

## 测试 1：Agent 两两握手

目标：验证所有固定角色与后续新建角色是否具备基本 A2A 通信能力。

### 发送模板

```text
我是XXagent，你是谁？
```

### 回复模板

```text
我是XXagent，我的能力是XXX。
```

### 要求

- 每个 Agent 都要给每个 Agent 发一次
- 必须记录日志
- 必须记录成功/失败次数
- 若失败，检查 JSON 协议、session 路由、日志路径是否正常

## 测试 2：静默任务测试

目标：验证安装后所有 agent 是否还能持续工作，并完成一次完整协作链。

### 任务

```text
搜索 GitHub 最近 7 天 star 涨得最快的 10 个项目，总结共同特点。
```

### 期望

- 主Agent 负责唯一用户出口
- AgentPool 生成对应角色
- A/B 两组并行完成调研
- 审核Agent 评分并择优
- 检查Agent 在执行中持续巡检
- 输出必须去重

## 测试 3：恢复测试

目标：验证 stale / watch agent 能否被检查Agent识别并恢复。

### 要求

- 人工制造一个无动作队列项
- 运行巡检脚本
- 确认产生唤醒或恢复建议
- 必要时执行 retry / 重派 / 重建

## 测试 4：原生 session 调度测试

## 测试 5：分阶段可恢复流水线测试

目标：验证完整链路可以拆阶段执行，并在中断后继续。

### 命令

```bash
./scripts/stage1_plan.py "/mac 调研最近 7 天值得关注的 OpenClaw 多Agent 项目，并总结协作优点"
./scripts/stage2_workers.py examples/generated/staged-runtime/pipeline-state.json --worker-agent-b exec-worker-2
./scripts/stage3_review_final.py examples/generated/staged-runtime/pipeline-state.json
./scripts/test_stage3_smoke.py examples/generated/staged-runtime/pipeline-state.json
./scripts/resume_pipeline.py examples/generated/staged-runtime/pipeline-state.json --worker-agent-b exec-worker-2
./scripts/run_staged_pipeline.py "/mac 调研最近 7 天值得关注的 OpenClaw 多Agent 项目，并总结协作优点" --worker-agent-b exec-worker-2 --stop-after stage2
```

### 检查点

- 是否生成 `pipeline-state.json`
- stage 字段是否从 `stage1_done` → `stage2_done` → `stage3_done`
- 中断后能否从已有状态继续
- 最终是否产出 worker / review / final / session_probe
- `validate_pipeline_state.py` 是否能校验通过
- `inspect_and_recover.py --auto-resume-pipeline` / `--auto-repair-pipeline` 是否能执行精确恢复动作
- `test_recovery_pipeline_smoke.py` 是否能完成 broken state → repair/resume → validate 闭环
