# 安装与使用

> 目标：安装简单、默认接管、可验收、可恢复。
> 这份文件承担真正的安装入口、默认接管说明、命令入口说明、安装后测试导航。

---

## 一、安装目标

安装完成后，理想状态是：

- 用户装完 skill，**默认就在和我们的主Agent体系打交道**
- 普通复杂任务，默认由 **Multi-Agent-Collaboration** 接管
- 显式 `/mac <任务>`，必须强制进入多会话协作模式
- 主Agent 是唯一用户出口
- 默认常驻只保留 4 个核心角色：
  - `main-ceo`
  - `pool-hr`
  - `review-judge`
  - `inspect-patrol`
- specialist 不预建一大堆，只有在任务真的需要时才创建或复用

> 一句话：**先把主控层做扎实，再按需招聘子Agent。**

---

## 二、安装 skill

推荐直接运行：

```bash
./scripts/default-takeover-setup.sh
```

它会做三件事：

1. 把 `skills/multi-agent-collaboration/` 安装到共享 skills 目录
2. 把 `skills/mac/` 一并安装，作为 `/mac` 命令桥
3. 初始化 `mac-system/` 基础工作目录

如有需要，重新打开 session 或重启 gateway 让 skills 刷新。

---

## 三、安装前必须确认的 OpenClaw 配置

本 skill 要成为 **OpenClaw 原生多会话版**，依赖平台自己的 agent-to-agent 与 session 能力。

### 最关键配置

请确认真实配置字段是：

```json
{
  "tools": {
    "agentToAgent": {
      "enabled": true,
      "allow": [
        "main-ceo",
        "pool-hr",
        "review-judge",
        "inspect-patrol",
        "exec-worker-1",
        "exec-worker-2"
      ]
    }
  }
}
```

### 你的要求如何正确落地

你要求：
- `tools.agentToAgent.agentToAgent=true`
- allow 允许所有 agent

这里要纠正为 **真实字段名**：

- `tools.agentToAgent.enabled = true`
- `tools.agentToAgent.allow = [...]`

如果你想做到“允许当前所有 agent”，正确做法是：

- 把当前已知 agent id 全部写进 allow 列表
- 后续每新增一个 specialist，再同步补进 allow

而不是写错字段名。

### 建议同时确认

如果你的环境里有可见性配置，建议同时确认：

```json
{
  "tools": {
    "sessions": {
      "visibility": "all"
    }
  }
}
```

> 这样更利于多 agent/session 的可见性与排障。

## 四、关于“安装完默认接管所有 agent”

你要的最终目标很明确：

- 安装完 skill 后，平台级默认接管所有 agent
- 用户装完之后，直接就在和我们 skill 创建的主Agent 对话

这件事要拆开理解：

### 1. 我们能直接做到的
- 提供主 skill：`Multi-Agent-Collaboration`
- 提供显式入口：`/mac`
- 提供默认接管规则：复杂任务优先走本 skill
- 提供主控层角色与流程纪律

### 2. 还取决于平台配置 / 当前默认 agent 的
- 哪个 agent 是默认 agent
- 哪些 agent 暴露给当前入口
- skills 是否被当前 agent/workspace 加载

### 3. 最稳的目标态
把 `main-ceo` 作为默认用户入口 agent。

这样：
- 用户平时直接对话，就是在和主Agent 打交道
- 普通复杂任务，主Agent 自动判断是否进入多会话
- 用户输入 `/mac` 时，直接强制进入多会话协作

## 五、/mac 命令怎么理解

你要求：
- TUI / GUI / TG 都要效果
- `/mac` 直接进入多 agent
- 普通对话也尽量由本 skill 默认接管

### 正确落地方式

本仓库已经提供：

- `skills/mac/SKILL.md`

它的作用是：
- 作为显式命令桥 skill
- 在支持 slash-like skill entry 的场景里，尽量让 `/mac` 成为明显入口
- 即使平台不把它显示成真正的 slash command，也要把纯文本 `/mac ...` 视为强触发词

### 所以用户的三种使用方式都成立

#### 方式 1：直接对话
安装后，复杂任务默认就应由主Agent 按本 skill 接管。

#### 方式 2：显式 `/mac`
```text
/mac 调研最近 7 天 GitHub star 增长最快的 10 个项目，并总结共同特点
```

#### 方式 3：直接点名 skill
```text
使用 Multi-Agent-Collaboration skill 完成这个任务
```

## 六、推荐的默认角色设计

安装完成后，**不要预建一大堆 specialist**。

默认只保留 4 个核心角色：

### 1. 主Agent `main-ceo`
职责：
- 理解任务
- 判断是否缺细节
- 任务拆解
- 调度团队
- 合并去重
- 唯一用户出口

### 2. AgentPool `pool-hr`
职责：
- 分析能力缺口
- 判断复用还是招聘
- 设计 A/B 双组
- 给每个新角色写死边界
- 低质量角色淘汰 / 替换 / 重新招聘

### 3. 审核Agent `review-judge`
职责：
- Reviewer（格式）
- Judge（质量）
- Metrics（评分）
- 择优、驳回、打分、记录权重依据

### 4. 检查Agent `inspect-patrol`
职责：
- 心跳检测
- 行为检测
- 检查日志、队列、产物
- stale 判定
- retry / 唤醒 / 重派 / 重建建议

### specialist 原则
- 不预建海量子Agent
- 只有在任务明确需要时才新建或复用
- 每个 specialist 都要有：
  - 独立记忆目录
  - 独立日志目录
  - 独立 queue 文件
  - abilities.md
  - 明确能做/不能做的边界

## 七、你要求的“公司化系统”应该怎样落地

你要的是：
- 公司制
- 竞争机制
- 权重系统
- 自我优化
- 缺什么才招聘
- 人不行就解雇再招

正确实现顺序应该是：

### 第 1 层：先做最小闭环
- 主Agent
- worker
- reviewer
- inspect
- 去重收口

### 第 2 层：再上 A/B 双组竞争
- A组：稳定优先
- B组：激进优先

### 第 3 层：再加权重系统
依据：
- 审核通过率
- Reviewer/Judge/Metrics 评分
- 返工率
- 恢复后成功率
- 最近健康度

### 第 4 层：再加自动招聘 / 淘汰
- 复用高分角色
- 淘汰长期低分角色或整组
- 缺什么补什么
- 不让团队无限膨胀

> 顺序不能倒。先闭环，再竞争，再评分，再淘汰，才稳定。

## 九、推荐人工观察方式

如果你想看多 agent 协作过程，推荐：

1. 多开几个 SSH/TUI 窗口
2. 用 `/agent` 切到不同 agent
3. 分别观察：
   - `main-ceo`
   - `pool-hr`
   - `review-judge`
   - `inspect-patrol`
   - 某个 worker

这样最容易发现：
- 通信是否真的发生
- 会不会跑偏
- 有没有重复说话
- 有没有假装工作

## 十、自学习与自动进化应该怎么做

你要求：
- skill 能经常自动去网上搜索相关 skill
- 自我学习
- 自我完善

这个方向可以做，但**不能直接自动改主 skill**。

正确闭环：

```text
外部搜索 / 抓取
-> 写入 research/
-> 审核Agent 提炼优点与风险
-> 主Agent 决定是否吸收到 skill/docs/scripts
-> 跑测试
-> git 中文 commit
```

也就是说：
- **先 research，后吸收**
- 不能直接野蛮改主实现
- 自进化必须受审核

## 十一、git 记录原则

你要求：
- 用 git 记录所有 agent 的记忆、日志、创建的东西
- commit 要用中文
- 尽量减少硬盘消耗

建议执行原则：

- 只记录“有价值的状态变化”
- 不要把所有中间垃圾都塞进仓库
- 研究资料、结构化样例、关键日志、测试报告可记录
- 临时缓存、超大文件、重复快照要忽略
- commit 用中文，说明这次改了什么、为什么改

## 十二、使用方式（最终版）

用户只需要记住 3 句：

### 1. 普通复杂任务直接说
安装后，复杂任务默认就走本 skill。

### 2. 想强制进入多 agent，就用 `/mac`
```text
/mac 帮我做一个多步骤调研，并输出结构化报告
```

### 3. 想显式点名也可以
```text
使用 Multi-Agent-Collaboration skill 完成这个任务
```

---

## 十三、最终原则

- 只有主Agent 可以联系用户
- 非主Agent 禁止和用户通信
- 任务优先结构化成 JSON task packet
- 能单会话解决就别乱扩编
- 真要多会话，就按最小够用团队来
- 需要高可靠性再启用 A/B 双组竞争
- 自学习先落 `research/`，审核后再吸收
- 任何用户可见消息，主Agent 发出前必须去重

---

## 十四、一句话总结

**安装完后，普通复杂任务默认归它管；想强制进入多 Agent，就用 `/mac`；真正对用户说话的，永远只有主Agent。**
