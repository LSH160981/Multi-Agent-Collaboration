# 自动自学习方案（最终版）

## 目标

让本 skill 周期性学习新的多 Agent 协作方案，并把真正有价值的部分吸收到自己的：

- 项目骨架
- 伪代码
- 通信协议
- 审核体系
- 恢复体系
- 测试体系

而不是只做“收集链接”。

---

## 当前原型脚本

```bash
./scripts/analysis/auto_evolve_learning.py
```

可选带审核：

```bash
./scripts/analysis/auto_evolve_learning.py --with-review
```

它现在会：
1. 抓取候选资料
2. 写入 `research/auto/raw/`
3. 生成 `learning-summary-*.md`
4. 生成 `learning-packet-*.json`
5. 若启用 `--with-review`，让审核Agent给出结构化建议
6. 额外生成 `evolve_plan`，指出下一步优先该改哪些文件

---

## 学习来源

优先级如下：

1. OpenClaw 官方文档
2. ClawHub 上相关多 Agent skill
3. GitHub 上的多 Agent / orchestration / collaboration 项目
4. 博客文章、架构分享、案例复盘

---

## 每次学习提取什么

每次学习至少提取以下维度：

1. 角色设计
2. 项目骨架
3. 通信协议
4. 任务状态机
5. 审核评分机制
6. 巡检与恢复机制
7. 伪代码与执行流程
8. 自动化测试方法
9. 如果吸收，应该改哪些文件

---

## 学习结果落地

学习不是看完就算，而是必须落地到仓库：

- 写入 `research/`
- 更新 `SKILL.md`
- 更新 `伪代码.md`
- 更新 `逻辑执行流程.md`
- 必要时更新 `通信协议.json`
- 必要时更新测试模板与恢复策略
- 若审核判断 `code_first`，优先改 `scripts/` 下运行层

---

## 自学习边界

允许：
- 搜索资料
- 阅读资料
- 提炼优缺点
- 改进本仓库文档与模板
- 用 git 留档

禁止：
- 未经明确要求擅自升级系统
- 未经明确要求修改用户私有配置
- 未经明确要求向外部发送消息
- 把未经验证的外部设计直接强塞进生产流程

---

## 与 git 的结合

每次真正吸收改动后：

1. 先写研究笔记
2. 再改文档或模板
3. 最后 git commit

要求：
- commit message 使用中文
- 尽量做结构化小步提交
- 减少无意义缓存和大文件，节省硬盘

---

## 当前推荐闭环

> 先抓取 → 再审核 → 再生成 evolve_plan → 再由主Agent决定吸收改哪些文件

这才是本 skill 的“自动学习 + 审核后自进化”。
